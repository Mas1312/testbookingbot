# Прототип Telegram-бота для записи (Mini App)

Локальный рабочий прототип: клиент открывает бота в Telegram → нажимает кнопку
«Записаться» → открывается Mini App (веб-страница внутри Telegram) → выбирает
услугу, дату, время → запись сохраняется в базу.

Пока это **однобизнесовый** прототип (одна база услуг), но структура кода уже
написана так, что превратить его в мультитенантную SaaS-платформу (несколько
бизнесов) — это добавление колонки `business_id` в таблицы, а не переписывание
с нуля.

**Универсальность.** Позиции бывают двух типов, поэтому подходит не только для
записи по времени:
- **По расписанию** (`type: "slot"`) — клиент выбирает дату и время. Подходит
  для стрижки, аренды сапборда, консультации, массажа — чего угодно, где нужен слот.
- **Разовый заказ** (`type: "order"`) — без выбора времени, сразу оформление с
  количеством. Подходит для шаурмечной, доставки, продажи товара — чего угодно,
  где расписание не нужно.

К каждой заявке клиент может оставить **комментарий** (аллергии, пожелания,
"нужен именно мастер Х" и т.п.) — он виден владельцу в админке.

**Админ-панель.** Владелец бизнеса (его Telegram ID указывается в `.env`)
видит в той же Mini App переключатель «Запись / Управление»:
- **Заявки** — список всех записей/заказов с фильтром по статусу
  (новая / выполнена / отменена), с комментарием клиента, с кнопками
  «Выполнено» / «Отменить».
- **Позиции** — добавление, редактирование и удаление услуг/товаров прямо
  из телефона, без правки кода.

## 1. Что где лежит

```
tg-booking-bot/
├── backend/
│   ├── config.py       — все настройки: токен бота, адрес Mini App, рабочие часы
│   ├── database.py     — работа с SQLite: услуги, записи, расчёт свободных слотов
│   ├── server.py       — FastAPI-сервер: отдаёт API + саму Mini App
│   └── bot.py          — сам Telegram-бот (aiogram), кнопка открытия Mini App
├── webapp/
│   ├── index.html      — разметка экранов Mini App
│   ├── style.css       — оформление (подстраивается под тему Telegram)
│   └── app.js          — вся логика: шаги выбора, запросы к API, кнопка подтверждения
├── requirements.txt    — зависимости Python
├── .env.example        — шаблон файла с настройками (токен и т.п.)
└── booking.db          — база данных SQLite (создаётся сама при первом запуске)
```

**Как это связано между собой:**
- `bot.py` — это то, с чем разговаривает пользователь в Telegram. Он не содержит
  логики записи, только присылает кнопку с web-ссылкой.
- `server.py` — веб-сервер. Он одновременно:
  1) отдаёт файлы из `webapp/` (саму мини-апку), когда Telegram её открывает;
  2) обрабатывает запросы этой мини-апки типа «дай список услуг», «забронируй слот».
- `database.py` — вся работа с SQLite вынесена сюда, чтобы `server.py` не был
  захламлён SQL-запросами.
- `app.js` — это фронтенд, который выполняется в браузере (внутри Telegram).
  Он ничего не знает про Python, только дёргает `/api/...` через `fetch`.

## 2. Установка (один раз)

Нужен Python 3.10+.

```bash
cd tg-booking-bot
python3 -m venv venv
source venv/bin/activate          # на Windows: venv\Scripts\activate
pip install -r requirements.txt
```

Скопируй файл настроек:

```bash
cp .env.example .env
```

И открой `.env` — понадобится токен бота (как получить — см. ниже), а также:
- `BUSINESS_NAME` — название твоего бизнеса, покажется в шапке Mini App
- `OWNER_TG_ID` — твой личный Telegram ID. Узнать его просто: напиши боту
  `@userinfobot` — он пришлёт числовой ID. Только этот ID увидит вкладку
  «Управление» в Mini App — у всех остальных будет только обычная запись.

---

## 3. Получаем токен бота

1. В Telegram открой **@BotFather**
2. Отправь `/newbot`, придумай имя и username (должен заканчиваться на `bot`)
3. BotFather пришлёт токен вида `123456789:ABCdef...` — вставь его в `.env` в поле `BOT_TOKEN`

## 4. Запуск локально

Тебе нужно **два запущенных процесса одновременно**: сервер (API + Mini App) и бот.
Проще всего — два окна терминала.

**Терминал 1 — сервер:**
```bash
cd tg-booking-bot/backend
python3 -m uvicorn server:app --reload --port 8000
```
После этого на `http://localhost:8000` открывается сама мини-апка (можно
глянуть в обычном браузере — она отрисуется, просто не будет данных о
пользователе Telegram, это нормально для отладки вёрстки).

**Терминал 2 — бот:**
```bash
cd tg-booking-bot/backend
python3 bot.py
```

### Важный момент: Telegram Mini App требует HTTPS

Telegram не откроет кнопку с `web_app`, если ссылка — обычный `http://localhost`.
Нужен публичный HTTPS-адрес. Для локальной разработки проще всего пробросить
локальный сервер наружу через **ngrok**:

```bash
# установи ngrok (https://ngrok.com/download), затем:
ngrok http 8000
```

Ngrok выдаст адрес вида `https://abcd1234.ngrok-free.app` — вставь его в `.env`
в `WEBAPP_URL` и перезапусти `bot.py` (сервер перезапускать не нужно, если
работает с `--reload`, но `.env` он не перечитывает "на лету" — перезапусти на
всякий случай оба процесса).

После этого:
1. Открой своего бота в Telegram
2. Отправь `/start`
3. Нажми кнопку «📅 Записаться» — откроется Mini App внутри Telegram

## 5. Как проверить, что записи сохраняются

Прототип пока без визуальной админки, но есть служебный эндпоинт:

```
GET http://localhost:8000/api/bookings
```

Открой этот адрес в браузере (пока сервер запущен) — увидишь JSON со всеми
записями. Полноценную админ-панель для владельца бизнеса имеет смысл делать
отдельным экраном Mini App на следующем этапе.

## 6. Как поменять услуги и рабочие часы

- **Услуги/товары** — теперь не нужно лезть в код: открой Mini App под своим
  Telegram ID (тем, что в `OWNER_TG_ID`), перейди во вкладку «Управление» →
  «Позиции» → «+ Добавить позицию». Стартовый демо-набор всё ещё задан в
  `backend/database.py` (`demo_services`) и сидируется только при первом
  запуске (когда `booking.db` ещё не существует).
- **Рабочие часы, шаг сетки, на сколько дней вперёд открыта запись** — всё в
  `backend/config.py` (`WORK_START_HOUR`, `WORK_END_HOUR`, `SLOT_STEP_MINUTES`,
  `DAYS_AHEAD`). Это общие настройки для всех позиций типа «по расписанию».

## 6.1. Важное про безопасность прототипа

Проверка «ты владелец или нет» в этой версии — простая сверка присланного
`Telegram ID` с тем, что в `.env`. Для локального теста и демонстрации этого
достаточно, но для реального продакшена (особенно если бизнесов будет
несколько) стоит валидировать `initData` от Telegram по HMAC-подписи, а не
просто доверять ID, который прислал клиент — иначе теоретически можно
подделать запрос. Это отдельная задача на следующий этап.

## 7. Если что-то не работает

- **Кнопка в боте не открывает Mini App / пишет ошибку** — почти всегда причина
  в том, что `WEBAPP_URL` в `.env` не HTTPS или ngrok-туннель уже "протух"
  (бесплатный ngrok даёт новый адрес при каждом перезапуске — не забывай
  обновлять `.env`).
- **"Address already in use" при запуске сервера** — порт 8000 уже занят
  предыдущим запуском. Останови его (`Ctrl+C` в том терминале) или смени
  `SERVER_PORT` в `.env` и в команде `--port`.
- **Слоты не совпадают с ожиданиями** — логика в `database.py` в функции
  `get_available_slots`: она вычисляет занятость в минутах от полуночи и
  проверяет пересечение интервалов, плюс на сегодняшний день скрывает уже
  прошедшее время.

## 8. Что дальше (если продукт заходит)

Это MVP для одного бизнеса. Следующие логичные шаги к SaaS-версии:
1. Добавить `business_id` во все таблицы + таблицу `businesses`
2. Экран онбординга нового бизнеса (свой бот через BotFather API или один
   общий бот + `business_id` в ссылке Mini App)
3. Простая админка внутри Mini App (для владельца — отдельный режим по флагу
   "я владелец")
4. Напоминания клиентам (фоновый воркер + `bot.send_message`)
5. Оплата подписки владельцем через Telegram Payments
